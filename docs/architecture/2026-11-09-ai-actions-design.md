# AI Action 第一阶段设计

日期：2026-11-09。状态：用户已审阅批准，按此边界实现并验收。

## 目标与范围

让办公用户在工具内总结、分类、提取、翻译和生成文本。用户不需要知道 Action 标识。复用 DSH 的模型提供方、连接设置和模型适配，不实现第二套模型配置或聊天运行时。不读取现有密钥、不调用真实模型额度验收。

本阶段只交付 AI Action。高质量业务模板、跨工具结果传递、持久任务恢复与撤销、个人偏好、额外能力插件和工具版本回退分别作为后续阶段；暂停的自然语言能力匹配不恢复。

## 代码现状与决定

- `service/actions/registry.py` 当前注册两个确定性文件处理 Action；输入输出由 Pydantic 声明，TypeScript 客户端从同一模型生成。
- `service/actions/runtime.py`、`service/tools/tool_jobs.py` 已提供后台任务、单工具串行和安全取消。`ToolOutputs` 仅发布完整结果，保留结果历史。
- `electron/workspace/src/bridge.ts` 的 stdio 为宿主私有请求/响应接口；fd 3 只承载可信进程生命周期元数据，不承载 AI 内容。
- 固定版本 DSH 的 `packages/llm/llm/src/index.ts` 提供 `ctx.llm.stream`，处理模型适配和终止状态。不能通过自行构造 HTTP 请求绕过 DSH。
- 当前工具没有 AI 请求授权接口。新增的接口必须绑定实际运行中的工具实例，不能信任模型或 iframe 提供的身份、授权结论或任意连接地址。

选择：在现有 Action 执行边界增加宿主代理能力，工具提交候选请求，宿主确认后直接调用 DSH LLM。不上新聊天 Agent、不启动子 Agent、不开放模型工具调用。

## 用户流程

1. 工具提供“总结内容”“分类”“提取字段”“翻译”“生成内容”等业务操作。
2. 用户操作工具时创建一个待确认的 AI 请求，冻结本次任务、文本、输出约束和请求标识。
3. 宿主在 iframe 外显示确认面板：来源工具、操作、实际待发送文本、内容长度、目标模型，以及是否将发送给外部模型服务。不能把本地模型一概称为外部服务。
4. 用户从 DSH 当前可用模型中选择目标，确认本次发送。默认不发送完整聊天历史、工具源码、其他附件或日志；文件内容仅限工具明确转换并列在面板中的文本。
5. 确认后宿主执行一次有界模型调用，返回有效结果。工具显示进度，成功后可展示内容并通过结果区下载文本或 JSON。
6. 拒绝、超时、断开或取消时明确结束本次请求。网络失败或结果未知时不自动重试；用户主动重试创建新的确认。

首版不提供长期免确认、批量永久授权或后台定时模型调用。设置默认模型不是对后续内容发送的授权。

## 授权与通信

使用既有私有 stdio 由 TypeScript 宿主发起查询，Python 执行器代理访问所拥有工具进程的宿主专用控制接口。工具只能提交待确认请求，不能从工具来源访问审批、模型连接或完成结果写回接口。

宿主控制接口使用当前工具进程的内部鉴权，和 iframe 的普通业务会话权限分离。不得将宿主令牌或模型密钥传入 iframe、工具源码、Action 参数、状态文件或日志。fd 3 继续只处理进程生命周期。

待确认内容存于进程内，最长十分钟。授权绑定宿主生成的请求 ID、工具身份、实际 worker/run、源码指纹、任务及输出约束摘要、完整待发送内容摘要和选定模型。确认使用冻结的快照；任何变化、刷新、进程重启或过期均失效。审批接口重新校验绑定，不能仅相信客户端的 confirmed=true。

同一请求只能从待确认转为拒绝、过期或执行中一次；重复点击或迟到回执不产生第二次模型调用。发布和工具关闭沿用现有任务生命周期检查。

## Action 输入输出

用统一文本能力承载五种任务，具体技术标识仅对程序和 Agent 可见。参数包括任务、明确输入文本、必要的语言/分类标签/字段约束，不接受任意 provider URL、密钥、文件路径、工具列表或系统指令。

- 总结、翻译、生成：有界纯文本输出。
- 分类：结果必须命中本次给定的有限标签集合。
- 提取：支持明确的有界简单字段类型、必填约束和数组限制；不接受可执行的动态验证器。
- 输入长度、输出长度、执行时限和并发数均有宿主上限，工具只能收紧，不能放大。

结果沿用 Action 的 invocation ID、版本、状态、输出文件引用与数值统计。文本保存为新 `.txt` 文件，结构化结果校验通过后保存为新 `.json` 文件；工具可以通过自己的结果 ID 读取和展示，不需要新文件权限。原始业务输入不覆盖。

模型返回工具调用、长度截断、错误终止或不符合约束的 JSON 均为失败，不把半成品作为成功结果发布，也不静默调用模型修复输出。文本不作为 HTML 执行，模型返回内容不是指令。

## 执行、取消和日志

复用 ToolJobs 和 TypeScript 宿主任务机制。待确认占用一个可取消请求，不持有数据库事务或在宿主工具队列中阻塞审批回路；审批与状态查询不能排在等待模型的任务后面，避免死锁。

AI 网络等待可以通过 AbortController 停止；一旦取消，不接受迟到输出。结果文件写入使用现有原子发布机制，开始落盘后先完成该次文件写入，不强制终止写文件。后台任务取消不会自动撤销已完成的结果。

日志只记录请求/调用关联标识、工具和模型身份、任务类型、长度、时长、用量（DSH 有报告时）和安全错误分类，不记录输入正文、完整模型结果或密钥。不把业务内容写入 DSH 聊天消息、Calabash 任务日志或第二套追踪系统。对 DSH 当前扩展/追踪中间件的接入边界需要在实现中验证，不能声称所有用户自行安装的受信任插件都是沙箱。

## 实施顺序

1. 实现可用模拟适配器覆盖的宿主 AI 请求/授权状态机和受限工作进程通道。
2. 接入 DSH 模型目录与单次流调用，禁止工具调用及额外 Agent 循环。
3. 实现 iframe 外确认面板与模型选择；工具仅提交业务候选。
4. 接入 Action、生成类型、进度、文本/JSON 结果交付及 Skill。
5. 完成源代码、真实 DSH 模拟模型、安装包三个层级验收。

## 验收标准

全部使用临时目录、合成内容和模拟模型，不读取真实密钥或业务数据。

- 未确认、拒绝、过期、内容/模型/源码变化或跨工具伪造时，模型调用次数为零。
- 用户确认的内容与适配器收到的内容完全一致；没有隐式追加聊天、附件、日志或密钥。
- 五种任务正常完成；非法分类、缺字段、错误类型、无效 JSON、超长或截断输出不发布结果。
- 无效模型或连接失败不自动重试；重复确认、断开重连和迟到回执不重复调用。
- 取消/刷新/退出不产生迟到成功或中断文件写入；不同工具状态隔离，审批无队列死锁。
- 模拟模型和日志捕获测试证明正文及密钥不落入宿主任务日志、操作回执或常规运行日志。
- 打包后在临时 HOME 下验证完整流程；不得通过真实提供方花费额度来替代合成验收。

## 边界

本方案不承诺实际模型输出的业务正确率。允许用户确认一次业务内容发送，不代表允许后续自动发送、启用插件、执行生成代码或修改系统权限。
