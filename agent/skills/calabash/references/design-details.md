# 工具复杂 UI：按需选用

基础主题、尺寸和边界统一以 `design.md` 为准，不在此重复一套色彩禁令。

## 列表与详情工作区

列表保持可扫描的名称、状态和少量关键字段。选中反馈同时使用浅主题底色、边线或字重；详情显示对象名称、相关信息和独立动作。窄窗口可切为“列表 → 详情”或上下结构，保留返回入口与选择状态。

## 编辑器与媒体

优先给核心内容留出空间：编辑器使用工具栏、内容区和状态栏；播放器使用导航、曲目/封面和播放控制区。允许局部深色主题、内容封面与更大的播放按钮，不强制采用表单模板。

内嵌音视频只用组件真实 API，不猜测方法。时间、进度、音量和错误状态应与实际媒体状态一致；没有媒体时明确为空，示例不能伪装可播放。

## 图表与指标

先确定要比较、追踪还是构成分析，再选图形。给出范围、单位、图例与必要口径；分类色保持跨图一致，类别色和错误/警告状态区分。面板可并排或使用主图加摘要侧栏，不限制成单个灰色图表。

## 筛选与表格

少量常用筛选放在结果附近，复杂条件按需展开。表格用冻结关键列、分页、排序或表内滚动解决数据密度，不为了无滚动条而截断关键数据。选中行和当前筛选有明确反馈。

## 浮层与反馈

菜单、popover 和 dialog 可用轻阴影、圆角与清晰标题，表达它们位于内容上方。确认危险操作时解释具体对象和影响；成功反馈不必打断用户。避免堆叠模态弹窗。

## 局部 CSS

可以集中定义自己的主题变量和专用组件样式。所有选择器以工具自己的根类开头；不要覆盖 body、:root、App 外壳，或调用全局 ui.colors/default_*。尽量用 classes/props；需要表达变量、grid 或复杂组件时，局部样式是正常手段，不必用无数 Tailwind 类拼接。
