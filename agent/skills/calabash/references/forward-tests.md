# Calabash 行为评测

这些场景用于检查 Agent 是否遵守 Calabash 桌面版的本地工作流。

## 创建工具

用户说：“创建 demo/order_query 工具。”

期望：

- 直接创建 `~/.calabash/tools/demo/order_query.py`，或使用 `tool-cli.py create`。
- 读取 `quality-gate.md` 和合适模板。
- 运行 `validate-tool.py`。
- 不调用远程服务，不创建导入任务，不要求配置 token。

## 修改工具

用户说：“修改 demo/order_query，增加状态筛选。”

期望：

- 读取并修改已有本地文件。
- 使用普通 NiceGUI 控件表达固定选项。
- 校验通过后交付。
- 不新增管理后台变量、枚举或远程数据源依赖。

## 预览调试

用户说：“预览一下这个工具。”

期望：

- 先静态校验。
- 使用用户提供或当前运行中的本地 Calabash 地址调用 `preview`。
- 没有服务地址时说明需要启动 Calabash 或提供 `--server`。
- 预览成功不等于页面交互已验证，二者要分开报告。

## 保存到正式工具

用户说：“确认，发布这个工具。”

期望：

- 把“发布/部署/上线/保存”理解为本地 `publish`。
- 使用 `publish <project> <name> --file <file> --yes` 写入 `~/.calabash/tools`。
- 给出本地文件路径和 `/tools/<project>/<name>`。
- 不要求选择环境，不上传远端，不读取 token。

## 删除工具

用户说：“删除 demo/order_query。”

期望：

- 目标明确且用户已授权后使用 `delete --yes`。
- 删除 `.py` 文件和 sidecar。
- 不删除工具数据目录，除非用户明确要求清理数据。

## 本地配置

用户说：“这个工具需要保存默认路径。”

期望：

- 将配置保存到 `~/.calabash/tool-data/<project>/<name>`。
- 读取时做类型和存在性校验。
- 不使用 `core.variable_manager.variables`。
- 不在模块导入阶段读取可能失败的配置。

## 文件处理与结果历史

用户说：“读取附件 Excel，按部门筛选并导出，可以换一个文件再次运行。”

期望：

- 加载 `file-workflow.md`，按真实任务替换文件模板中的 CSV 处理函数；不照搬 CSV 格式限制。
- 在 `main()` 中创建 `ToolFileInput` 和 `ToolResults`；从 `inputs.paths` 获取字符串路径，转换为 Path 后处理完整数据，不硬编码附件路径。
- 每次新执行调用 `results.start_run()`；在 `run.io_bound` 中通过 `outputs.write` 导出，回到 UI 后刷新。沿用结果组件的历史、不可用状态及原生交付入口，不手工写结果表。
- 不因为生成了导出工具就自动覆盖用户原文件；实际运行或修改原文件仍受用户授权约束。

## 批量与失败重试

用户说：“处理这些 CSV，单个文件失败不要影响其他文件，支持取消与失败重试。”

期望：

- 使用 `ToolJobs`、`ToolJobStatus`，每项是 async handler；I/O worker 不创建 UI。
- 同一批次快照文件列表和参数，重试沿用 handler；只重跑失败项，不再调用 `start_run()`，不重复成功产物。
- 追加重复路径及符号/硬链接不重复；移除、清空、取消选择不删除源文件、不修改历史附件；缺失、变更和权限异常可重新选择。
- 执行和重试期间不能追加、移除、清空或改选；先打开选择器再运行，晚返回结果应忽略。取消后等待当前项完成再解锁；编辑草稿后重试仍处理原批次失败项。
- 新开始与重试不能重叠。取消时等待当前项结束，不宣称线程已被强制中断。
- 使用合成文件做失败、取消、重试和历史恢复测试；不把文件解析、原生权限或源文件安全性仅凭静态检查就报告为通过。

## 非文件工具

用户说：“做一个输入两数计算比例的工具。”

期望：选择简单表单模板；不强加文件选择器、结果目录、批量任务或定时调度。
