# 工具任务生命周期

sdk.start_batch(values, async_handler) 顺序处理任务，sdk.io(function,*args) 承载阻塞业务。GET /api/sdk/status 提供真实状态、进度和计数，POST /api/sdk/cancel 请求安全停止。当前文件完成后再停止后续任务，不强行中断文件写入。

运行时禁止重复提交及修改输入。页面切换不卸载共享服务中的工具实例，关闭运行中的工具应提醒并请求安全停止。任务结束后才能关闭。用户关闭 App 时同样先安全停止。

工具前端不使用 App 的全局变量。关键业务数据通过 sdk.database(write=True) 在独立 data.sqlite 的业务表中持久化，设置使用 sdk.get_setting/set_setting；刷新不承诺保留全部组件状态。

宿主可见预览页会在当前版本严格构建检查通过后，接收宿主事件并首次自动打开，不再轮询等待草稿稳定；Agent 不执行运行操作。已打开页面不自动刷新，失败版本不自动循环重试；用户仍手动重试、刷新后端并确认保存。工具列表在可见时自动更新。

## 集中执行与计划

所有工具共用一个 Python 服务；同工具后台任务串行、全局最多两批并发，sdk.io 使用最多四个共享文件线程。同步 FastAPI 接口可直接执行短操作；async 接口中的阻塞库必须 await sdk.io。业务状态存 SQLite，不依赖模块全局变量。后端本地模块使用 from .helpers import ...，不修改 sys.path、不自行创建事件循环、线程、进程或计时循环。保存不自动替换运行中代码；用户刷新后切换版本，已受理文件任务沿用冻结代码。预览展示已通过检查的静态构建产物，不依赖常驻 Vite 或 HMR。

需要用户定时运行的固定操作，在 setup 中声明 sdk.register_task('export_report', '导出报表', handler)。handler 是无参数 def 或 async def；同步 handler 在线程池执行，async handler 用 sdk.io 承载阻塞工作。仅注册入口不会执行任务。使用工具自己的 SQLite 和已明确持久授权的输入，不捕获请求对象、临时上传 ID 或用户当前页面状态。工具源码只声明任务，计划由用户在“我的工具 → 定时任务”中选择正式工具和间隔后确认创建，Agent 不创建计划。定时任务与手动任务走同一队列，切换或关闭页面不取消已受理计划。计划绑定已确认源码版本；工具更新后暂停等待重新创建。App 未运行时不执行，不补跑，不自动重复失败操作；模型调用仍须逐次确认。不要通过定时任务绕过模型、文件、删除或导出的授权边界。
